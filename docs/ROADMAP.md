# Roadmap

Deferred ≠ declined (§12). Anything here may land once it passes three gates:
it fits the §04 vault contract (or bumps the major version with a documented
migration), it fits the §06 budgets or ships lazily, and it obeys §02. Process
is roadmap entry → ADR → milestone.

Three kinds of entry live here. The **§12 table** below is the designed expansion
path — features deliberately left out of v1, each with the landing path that
keeps it contract-safe. After it come risks and decisions **parked during a
phase**, recorded here rather than in a commit message nobody will re-read. Last
are things **decided after release**, raised by using the thing rather than by
building it: those are answers, not deferrals, and they are written down so the
same question is not re-argued with every new pair of eyes.

Every entry names a trigger — for a parked item, what would un-park it; for a
decided one, what would reopen it. An entry without one is a wish.

## Post-v1 expansion (§12, seeded by P11)

| Deferred feature | Designed landing path (contract-safe) | Prerequisite / trigger |
|---|---|---|
| **Query & table views ("databases")** | Inline queries over frontmatter + tags, evaluated client-side and rendered as §02 tables — the Dataview pattern. Notes stay plain files; a query is just text in a note. | Query-grammar ADR; v1 corpus/store stable. |
| **Kanban / boards** | A view over existing tasks + tags, columns keyed by tag or status. Pure derivation, zero new storage. | The query engine above. |
| **Graph view** | Pure derivation of the backlinks map into a monochrome, hairline-styled panel. No new data — `core/links.ts` already computes it. | Demand-driven; lazy chunk within budget. |
| **Plugin system** | Versioned, capability-scoped extension points (commands, panels, decorations, query functions) once the core API freezes at v1.x. A plugin may never bypass `vault.rs` writes. | API freeze + a security-model ADR. |
| **Richer editing surface** | ~~Images shipped in §04/§02b Rev O~~ — drawn *under* their own `![alt](src)` rather than in place of it, which keeps this row's own "markdown stays the literal source" and avoids answering the open §02 question about folding by accident. Tables and math remain, and both are the harder half: each would replace the source rather than annotate it. | For the rest: a §02 ruling on **replacing** the source, which is a different question from the one frontmatter folding just answered. §12 permits hiding "provided it still passes §02", and a fold passes because it is reversible in place and the bytes never move. A rendered table is not that — the source is gone while you look at the result, and there is nowhere to put the caret to get it back. |
| **Realtime co-editing** | Optional CRDT transport layered on top (reopening ADR-001). Files stay canonical; every session flushes to plain markdown. | True multi-writer demand. |
| **Built-in richer sync** | From git checkpoints (P12) toward managed git remotes or an optional relay — always self-hostable, never required. | P12 shipped; user pull. |
| **Importers** | One-way converters (Obsidian, Notion export, Logseq) into the §04 format. Read-only, low risk, high adoption value. | None — the best first post-v1 milestone. |
| **Native shells / mobile ergonomics** | A Tauri wrapper around the same embedded UI. Remote/tailnet mode already serves every device meanwhile. | PWA ergonomics measured insufficient. |
| **E2E-encrypted remote** | Token mode (P12) hardened with encrypted transport, for vaults hosted off-device. | Remote mode adoption. |

## Parked during P2 (server core)

| Item | Why it is parked | Trigger |
|---|---|---|
| **Etag collision window** | §04 mandates `mtime + len`, so two different bodies of identical length written inside one filesystem mtime tick share an etag. Measured sub-microsecond on macOS/APFS, so it is not reachable in practice there; ext4's granularity is coarser. Changing the etag scheme would change §04. | A real collision, or a §04 revision. The client rule meanwhile: an equal etag on a `changed` frame must **not** be read as "no change". |
| **~~Cross-process write races~~** | ~~Closed.~~ `serve` claims the vault before it binds and refuses when somebody else holds it, so the in-process lock is once again describing the truth. Three decisions are worth recording. The claim lives in the **temp directory**, not `.register/`: one untracked file there makes a vault under git permanently dirty for as long as the app runs — `?1` in the status bar, and the test that exists to say the app never touches your repository going red — and `.gitignore` cannot fix it, because adding a third line to the scaffold is a §04 surface change under hard rule 1 and would reach no vault anybody had already initialised. The cost of that, stated because it is real: two processes not sharing a temp directory cannot see each other's claim, and a container and its host mounting one vault is exactly that case. The mechanism is `create_new`, one filesystem operation that both creates and refuses, rather than `fs4` or `fd-lock` — real advisory locking, an ADR under hard rule 6, and the wrong shape anyway, since what is wanted is a refusal at startup and not a lock held across every write. And a claim whose pid is **gone is taken over rather than obeyed**, which the first version did not do: a process killed outright never reaches `Drop`, so without that one `docker kill` left a vault unstartable until a human deleted a file — a worse failure than the race, and a new one. Liveness is `kill -0` in a subprocess, since std exposes no `kill`; every way of not knowing answers "still held", because a stranded lock is an inconvenience with a printed fix and a stolen one is the thing this prevents. Graceful shutdown releases it: `with_graceful_shutdown` on SIGTERM and ctrl-c, which is what `docker stop` sends, and which finally uses the `signal` feature that had been enabled in `Cargo.toml` and called nowhere. | — |
| **Any loopback origin is trusted** | The origin guard allows `http://localhost:<any port>` so `pnpm dev` can proxy from vite. That grants the same authority to every other local web server. Narrowing it needs an explicit dev-origin flag. | P12, alongside token mode — the same conversation about who may talk to the server. |
| **~~No WebSocket keepalive~~** | ~~Closed.~~ `pump()` pings an idle socket every 30 s and bounds every send at 10 s. Both halves were needed and for different reasons: without the ping a connection that has died — a laptop closed on a tailnet, a NAT entry dropped — is indistinguishable from a quiet vault, so the socket stays open, the client believes it is live, and the next agent edit is delivered to nobody. Without the timeout a half-open socket takes writes into the kernel buffer until it fills and then blocks for good, holding the task and its broadcast slot for the life of the process. The cadence is a named field rather than a constant, `Checkpointer::with_idle`'s trick, so the test proves it in 60 ms instead of half a minute — and the test was checked against its own absence: remove the ping arm and it reports "no frame inside two seconds". | — |
| **`If-Match: *`** | RFC 9110 defines the wildcard as "matches iff the resource exists". Unimplemented; no client sends it. | A second client, or a spec revision that asks for it. |
| **Loopback is read as "the owner", and on a shared host it is not** | `decide()` exempts any loopback peer, so on a multi-user machine every other uid gets full read/write/delete over 127.0.0.1 — including on a vault whose mode 700 is keeping them out at the filesystem level. The signal that would settle it is a peer credential, and TCP does not carry one portably; `SO_PEERCRED`/`getpeereid` want a Unix socket, which is a §04 API-surface change rather than a patch. Documented in SECURITY.md meanwhile. | Anyone running this on a shared host — or a §04 revision that adds a socket transport. |
| **The released binaries are unsigned** | A tag now publishes `SHA256SUMS` alongside the five assets, which catches a corrupted or substituted download but proves nothing about who built it. Real provenance wants either cosign keyless signing or GitHub artifact attestations, and both add a workflow permission and a verification story that has to be documented or it is theatre. | The first release anyone but the author installs. |
| **~~`the_servers_own_atomic_write_reports_one_change_not_a_temp_file` is flaky~~** | ~~Closed.~~ Not a race with the coalescer and not really flaky: a **release** build failed it 24 times out of 24, which is what made it diagnosable. The fixture seeds its note before `Watch::start`, and macOS delivers those events to the stream anyway — the opposite of what the `ARM` comment claimed — so `drain` collected the seed's event alongside the write's and the assertion read as a debouncer leak. Arming now empties the channel rather than only waiting on it: 0 failures in 30 release runs and 15 debug runs, and removing the drain brings it back 5 times in 6. Harmless while the repository is one person's, and corrosive once it is public: a red run a contributor did not cause is how people learn to re-run CI without reading it. | The first time it fails a pull request that is otherwise green — or sooner, since the repository is now public. |
| **~~`cargo-audit` in CI~~** | ~~Closed after P11.~~ The trigger was "P10/P11 release engineering, where CI grows anyway", and it did — `ci.yml` now has an `audit` job. It is the check that would have found RUSTSEC-2025-0068 without ADR-001 having to find it by hand. | — |

## Parked during P12 (checkpoints + remote mode)

| Item | Why it is parked | Trigger |
|---|---|---|
| **~~GIT is permanently dashed~~** | ~~Closed by P12.~~ The tree envelope carries `{clean, ahead}` and §02b Screen 1's GIT field shows CLEAN / DIRTY / N AHEAD, or `—` when the vault is not a repository. | — |
| **A checkpoint sweeps the staging area** | It runs `git add -A`, so anything you had part-staged with `git add -p` joins the checkpoint. Off by default, and the alternative — committing only what the app touched — needs a list of what the app touched, which the watcher has but the committer does not. | Anyone using the index deliberately in a checkpointed vault. |
| **~~`git status` runs on every tree fetch~~** | ~~Closed.~~ `Vault` holds the last answer for 250 ms, which collapses a burst of tree fetches; a non-repository still costs one `rev-parse` and no more. | **Remote mode has no TLS** | Deliberate — §07's pattern is a tailnet, which is already encrypted, and terminating TLS is a reverse proxy's job. | **The token still has no revocation list** | ~~Partly closed:~~ `--token-file` and `REGISTER_TOKEN` mean it need not be an argv string visible in `ps`. What remains is the model — no accounts, no user table, no revocation, so rotating it means restarting the server. Right for a tailnet; thin for anything more exposed. | The same milestone as TLS. |

## Parked during P13 (§02b Screen 4)

screens make v1", built last because nothing scheduled it. What it left behind:

| Item | Why it is parked | Trigger |
|---|---|---|
| **The merge table has no j/k traversal** | Every cell is a button, so Tab reaches all of them and the dashed focus ring is correct — but §02b's nav-row model is `↑↓ / j–k` down a single column, and the table is a grid. | **The diff is line-level, not word-level** | A line with one word changed shows as two whole lines. Correct, and coarse. Word-level highlighting inside a contested row is presentational and would not change what is written; it is also a second diff to keep honest. | Someone merging prose rather than structure. |
| **`--signal` has a ninth consumer** | `UNRESOLVED` is signal-coloured, the same weight `External edit` carries, on the same argument: nothing else in the chrome means "your writing is somewhere you have not looked". §02 permits one signal colour and this is still it, but the token's own comment has read "status LED only" since P1 and has been false since P4. | A §02 ruling on what the accent is *for*, which would settle all nine at once rather than the newest. |
| **~~The vault contract still describes the manual route~~** | ~~Closed at your instruction (Rev S).~~ The instruction was true and stays first and unchanged, because an agent cannot click Screen 4 and merging the files by hand is still exactly what one should do. What is added is that a human has a second option — worth knowing precisely because an agent that merges a conflict its human meant to resolve on screen has destroyed the choice rather than made it. The order was also promoted from an order of words to a stated reason: merge first, delete second, because the merge being durable before the copy is retired is what makes a failure between the two leave *both* revisions on disk. `store.resolveConflict` has been written that way since P13 and `writes the merge before deleting the copy` has pinned it since — the contract simply never said why, so the test now cites it. It reaches new vaults only: `init` never overwrites, which is what makes re-running it safe, so a vault scaffolded before this keeps its wording. Editing files inside somebody's vault to fix that would be the worse of the two. | — |
| **A conflict of a conflict is refused, not merged** | Resolving takes the original's etag from the corpus. If the note moved again while you were choosing, the merge is refused and the table rebuilt — nothing is lost, both files stay, but you choose again from scratch. Re-deriving while preserving decisions means matching old rows to new ones, which is a merge problem inside a merge tool. | Anyone hitting it twice in a row. |

## Parked during P14 (the compatibility fixture)

§09's fourth testing layer — *"Compat · fixture vaults: a vault written by v1
opens unchanged in every later minor — §04 is the contract"* — was the one layer
that was neither built nor parked. It is built now: `tests/fixtures/vault-v1/` is
frozen and read by both parsers, and it found two live divergences on arrival.
What it left behind:

| Item | Why it is parked | Trigger |
|---|---|---|
| **An unreadable note is indistinguishable from an untitled one** | The other half of ADR-001, amended in this phase. A note whose frontmatter does not parse degrades to `title: null, tags: []` — which is right, since one bad note must not take `/api/tree` down, and is now a pinned contract. What is missing is any way to learn of it. Saying so in the tree means a new field in §04's envelope, a contract change under hard rule 1; saying so at startup means reading every note before the server binds, against §06's 500 ms start-to-editable budget. Both are real designs, neither is a decision to make in passing. | A §02b state for what an unreadable note looks like in the index — which would settle the envelope question at the same time. |

## Decided after v0.4.1 (an ultrawide monitor)

| Item | The decision, and why | What would reopen it |
|---|---|---|
| **The GIT field could never say anything in a container** | Fixed by giving the *developed* image a git to shell out to; the published one keeps `scratch`. **It was not an unknown**: `StatusBar.svelte`'s header comment had said "the container is `FROM scratch` and has no git binary, so it dashes there however the vault is stored" since 2026-08-07 (`7a35553`). It was written down in the one place only someone editing that component would read, never surfaced to a user, never given a roadmap entry, and never tested — which is how a known limitation and an unknown one become the same thing in practice. §02b Screen 1 draws GIT, §04 has `GET /api/tree` carry it, and §07 recommends the container — but `git::status()` shells out to the `git` executable and a `scratch` image has none, so `is_repo()` was false whatever the repository was doing. | **The GIT field did not speak git** | Changed to git's own shorthand (§04 Rev L). It read `CLEAN` or `DIRTY`, and `--dirty` is a git *flag*, not a word git prints — while the pair could not tell a vault with one untracked note from a vault mid-rebase. The data was already being fetched and thrown away: `status()` ran `git status --porcelain` and kept only whether the output was empty. So the envelope grew to `{branch, clean, staged, modified, untracked, ahead}` and the field is drawn the way `git status --short` and every shell prompt draw it — `MAIN`, `MAIN ~3`, `MAIN ↑2 +1 ~3 ?4` — with a mark only when its count is above zero. `clean` stays, and stays derived from the raw output rather than from the counts, so the two cannot drift apart silently. | **Checkpoints cannot commit from the container** | **Half closed, which was the half named "worth having regardless".** It no longer fails *silently*: `checkpoint()` answers `Committed | Nothing | Refused(reason)` and a refusal goes to stderr carrying git's own message, which for this case is the one that tells you how to fix it — *"Please tell me who you are"* and the two `git config` lines under it. Measured against a vault with no identity, and `docker logs` is where an operator will be looking. What remains is the identity itself: `git commit` needs `user.name`/`user.email`, the image sets neither, and inventing one for somebody's history is still not a default. | Passing an identity through compose, which is a `deploy/` decision rather than a code one — an operator who sets `GIT_AUTHOR_*` in their own compose file already has it working today. |
| **The frame rendered at exactly one size on every display** | Fixed, as a **plate scale** (§02 Rev K). Every §02 dimension now describes one plate unit and the product renders at whole multiples of it — 1× and 2× — applied as `zoom` on `<html>`, the same channel as `html.dark` and `html.teletype`. **No normative value moved**: `--text-body` is still the literal `13px`, and 1× is byte-identical to Rev J, which is why the frame-geometry assertions pass unmodified. The alternative, rewriting each token as `calc(13px * var(--scale))`, would have edited §02's numbers, double-scaled `--measure` (in `ch`) and the trackings (in `em`), and demanded a judgement call on all 26 addendum tokens — for an identical rendered result. Two questions were separated rather than answered together: *how big* is the user's, stored in `config.json` beside `scheme` and `bodyFace`; *is there room* is the canvas's, settled by one media query. That split is what makes a stored scale safe at all — §07 serves one vault to every device, so 2× chosen on the ultrawide is read verbatim by the laptop, where it is vetoed rather than obeyed. The breakpoints moved from `@media` to `@container` so they measure the frame in plate units instead of the raw viewport. | A display class the two stops do not serve — 5K/8K, where 3× is a one-word addition, or the 2000–2500 px band, which gets nothing and cannot get 1.5×. |

| **A container could never take over its own stale claim** | Fixed, and it was the takeover path's whole purpose defeated by the one deployment it was written for. `holder_is_gone` asks `kill -0`, and under an exec-form entrypoint the server is pid 1 — so a claim stranded by a `docker kill` reads `pid 1`, the replacement is also pid 1, and a process can always signal itself.
